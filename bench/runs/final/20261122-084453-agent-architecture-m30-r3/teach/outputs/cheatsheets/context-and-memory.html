Context and memory in an agent

What the model sees on each call, and what survives between steps and sessions. Token counts below are illustrative.

Key terms

TokenA small piece of text, roughly three quarters of an English word.
Context windowEverything the model sees on one call: instructions, tool descriptions, messages, tool results and its reply.
HistoryThe earlier messages and tool results the program sends again on every call.
CompactionTrimming history by clearing old tool results or summarising.
RetrievalKeeping long text outside the window and fetching only the few best chunks per question.
Notes (memory tool)Files the program saves outside the window, which the model reads in later sessions.

The four places information can live

  1. Window: the model only uses what is in this call, because it remembers nothing itself.
  2. History: resent in full on every step, so each call costs more than the last.
  3. Retrieval: for long shared text such as manuals, because sending it all every call is costly and a full window is not a better one.
  4. Notes: for slow-changing facts per student, because the window is gone when the chat ends. Fast-changing facts like the calendar are looked up fresh, or they go stale.

Cost rule in words: add up the input sent on every call. Total input = call 1 + call 2 + call 3, and each call holds everything before it plus the new lines.

Worked example

  1. Call 1 sends 1,225 tokens (instructions 400, tools 800, question 25). The model asks for the calendar (60 tokens).
  2. The tool returns 350 tokens. Call 2 sends 1,225 + 60 + 350 = 1,635. The model asks for the manual (70).
  3. The tool returns a 1,800-token page. Call 3 sends 1,635 + 70 + 1,800 = 3,505.
  4. Total input: 1,225 + 1,635 + 3,505 = 6,365 tokens, though the final window is about 3,595.

Common mistakes

  • The model remembers last visit on its own. Not so: only saved notes read back in carry over.
  • You only pay for the new message each step. Not so: the whole history is sent again.
  • A bigger window means put everything in. Not so: a fuller window is not used better.
  • A summary loses nothing. Not so: it can drop a key fact, like "not yet booked".
  • Retrieval always finds the right page. Not so: a chunk can miss its context, so add a line saying which machine and section it is from.
  • Notes are always right. Not so: they can go stale, so decide which record wins.
