Context and memory in an agent

Look here to decide where a piece of information goes: the context window, notes between sessions, or retrieval.

Key terms

TermPlain meaning
TokenA small chunk of text, roughly three-quarters of a word; windows are counted in it.
Context windowEverything the model sees on one call, with a size ceiling.
Context rotThe model recalls the contents less well as the window fills.
CompactionSummarizing the history and starting a fresh window from the summary.
Notes (memory tool)Files the program stores outside the window, so they survive between sessions.
Chunks, retrievalShort pieces of big documents; a search returns only the best few.

Rules

  1. The model only uses the text in the window, so a tool result must be added to it to be used.
  2. The model keeps nothing between steps; the program re-sends the whole history each call, so the input tokens you pay for add up.
  3. Old results clutter the window at any size, so clear or summarize them.
  4. A session's window is thrown away when it ends, so small facts to keep go in notes.
  5. Big documents go in a search, because pasting them in re-reads them on every call.

Two questions place anything: does it matter after this session, and how big is it?

Worked example

Booking, three calls: call 1 reads 1,418 tokens. Call 2 reads 1,418 + 30 + 120 = 1,568. Call 3 reads 1,568 + 30 + 40 = 1,638. Total read: 1,418 + 1,568 + 1,638 = 4,624, against 1,638 at the end. (Counts are made up for the arithmetic.)

Common mistakes

  • "The model looks things up itself." No: a tool result has to be added to the window.
  • "It remembers step 1 because it was just there." No: the program re-sends it.
  • "A bigger window fixes clutter." No: windows of every size get cluttered.
  • "It remembers students from earlier chats." No: only what was written down survives.
  • "Retrieval always beats pasting in." No: it pays off most when the text is big, and pasting re-reads it each call.
