Context and memory in an agent

Look-up sheet for what the model sees on each call, and what you save outside it. Sizes are the lesson's made-up examples.

Key terms

TermPlain meaning
TokenA small piece of text the model reads or writes; billed per token
Context windowAll the text the model can see on one call, including its reply
Context rotRecall gets worse as the window fills up
CompactionShrinking the history (clear old tool results, or summarize)
Chunk / retrievalA few-hundred-token piece of a manual / searching chunks and loading only the best few
Memory fileA note saved outside the window that a later session reads back

Three kinds of memory

KindWhat holds itAt session end
Within one callThe windowGone
Between steps of a requestHistory your program resends each callGone, unless saved
Between sessionsNotes, files or a databaseKept

Rules

  1. Cost of a call = tokens sent × price per token, because input is billed every call. At $2 per million: tokens × 2 / 1,000,000.
  2. Each call resends the whole history, because the model keeps nothing between calls.
  3. Big or rarely needed text goes behind retrieval, because it is costly and mostly irrelevant on any one call.
  4. Facts that must survive the session go in notes; facts that change go in a tool call, because notes go stale.

Worked example: a 3-call request

Base 1,000 tokens; a 500-token tool result is added after each of the first two calls.

  1. Call 1 sends 1,000.
  2. Call 2 sends 1,000 + 500 = 1,500.
  3. Call 3 sends 1,500 + 500 = 2,000.
  4. Billed: 1,000 + 1,500 + 2,000 = 4,500 tokens, which is $0.009 at $2 per million.

Common mistakes

  • "A token is a word." No: long or odd words split into several tokens.
  • "The model remembers last week." No: your program must send it again.
  • "Cost is the size of the question." No: the resent history dominates.
  • "The model searches the manual itself." No: your program runs the search.
  • "Save everything in notes." No: notes cost tokens on every read and go stale.
