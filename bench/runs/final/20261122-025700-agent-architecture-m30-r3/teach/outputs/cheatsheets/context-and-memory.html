Context and memory in an agent

Use this to decide where each fact lives: in the context window, looked up, or saved.

Key terms

TokenA small piece of text; limits and cost are counted in these.
Context windowAll the text the model sees on one call, including its own answer.
Conversation historyThe messages so far, kept and resent by the program.
Context rotRecall gets worse as the window fills.
CompactionSummarize a long chat and start a new window from the summary.
RetrievalSearch long text and put only the best chunks in the window.
Memory (notes)Files saved outside the window and read back later.

Rules

  1. Everything in a call counts (system prompt, tool definitions, messages, tool results), because the model reads all of it.
  2. The model keeps nothing between calls, so the program resends the history. Input = old history + new text.
  3. Clear old tool results and compact long chats, because a big window is not a better one.
  4. Use retrieval when the manuals are too long for the window. Count their tokens first (the lesson's advice).
  5. Notes carry soft facts between sessions. Rules that decide access come from the official record, through a tool.

Worked example

Call 1 input is 1,520 tokens. The model asks for the calendar (40 tokens) and the tool returns 150.

  1. Call 2 input = 1,520 + 40 + 150 = 1,710.
  2. Reply: 30 tokens. Student answers with 10 tokens.
  3. Call 3 input = 1,710 + 30 + 10 = 1,750, not 40. (All counts are illustrative.)

Common mistakes

  • "The model remembers me." Each new window starts empty; notes must be read back.
  • "A step costs only its new text." The whole history is resent.
  • "A 1M window means keep everything." Recall degrades and you pay for every resend.
  • "Retrieval teaches the model the manual." It only sees the chunks returned for this question.
  • "Notes are true." A note can be stale or only a student's claim.
