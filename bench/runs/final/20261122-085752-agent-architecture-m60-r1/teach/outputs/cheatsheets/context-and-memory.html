Context and memory in an agent

What the model sees on each call, what is saved, and how it finds one fact. Every number below is made up for the makerspace example.

Key terms

TermPlain meaning
TokenA piece of text the model reads or writes; about 100 tokens is 75 English words.
Context windowAll the text on one call: instructions, tool descriptions, history, and the reply.
ClearingDropping old tool results from the history.
CompactionSummarizing the chat and starting a fresh window from the summary.
ChunkA piece of a manual, about 300 tokens, that can be fetched alone.
BM25 / embeddingsScoring chunks by exact words / by meaning.
Top-kHow many best-scoring chunks go to the model.
LookupA tool that reads the current answer from the real record.

Rules

  1. The program resends the whole history on every call, because the model keeps nothing itself.
  2. Cost per request = input tokens across all calls at the input rate, plus output tokens at the output rate.
  3. Clear old tool results first, because they can be fetched again; summarize only when you must.
  4. Check a summary keeps the facts you cannot lose, before you shorten it.

Worked example (made-up prices: $2 in, $10 out per million tokens)

  1. Call 1 input: 800 + 600 + 30 = 1,430. Model asks for the calendar (40 out).
  2. Call 2 input: 1,430 + 40 + 350 = 1,820. Reply: 60 out.
  3. Input 3,250 × $2/M = $0.0065. Output 100 × $10/M = $0.0010. Total $0.0075.
  4. Pasting a 60,000-token manual into both calls: $0.2475, about 33 times more.

Common mistakes

  • "The model remembers the chat." No: the program resends it.
  • "A bigger window means stuff it all in." No: you pay per token per call, and recall gets worse.
  • "Output is free." No: it counts and costs more per token.
  • "Everything goes in notes." No: a saved "trained" note can be stale; look it up.
