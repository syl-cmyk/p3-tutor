Context and memory in an agent

By the end of this lesson you can say what your makerspace assistant keeps in its context, what it saves between sessions, and how it finds the right manual page.

Objective O3: context and memory in an agent About 10 minutes
Why this matters for you

Your assistant has to answer from long machine manuals and remember each student's training status between visits. Every token it reads costs money, so what you put in context is a design and budget decision you'll defend at the review.

The program adds the result to the conversation, then calls the model again with everything so far. That growing pile of text is what today is about.

The context window 2 min

The model only knows what's in the text you send it on this call. Nothing else. That text is the context, and the most it can hold is the context window, measured in tokens (Claude docs).

Here's what the assistant sends on its third call for "Is the laser cutter free tomorrow at 3 pm, and do I need training?":

  1. System prompt: "You are the makerspace assistant. Be brief." (about 200 tokens)
  2. Tool descriptions: check_calendar, search_manuals, check_training_record (about 600 tokens)
  3. Student's question (about 25 tokens)
  4. Call 1 result: calendar says 3 pm is free (about 100 tokens)
  5. Call 2 result: a manual page on the laser cutter (about 1,500 tokens)

That's about 2,400 tokens, and the model reads all of them again on every call. So the context grows each step, and you pay for it each step.

A common mix-up

"A bigger window means I can paste in every manual." Tempting, but more text costs more on every call, and the Anthropic engineers note that recall gets worse as the window fills ("context rot"). The goal is the smallest set of useful tokens, not the largest set that fits (Anthropic).

Between steps and between sessions 2 min

Context lasts as long as your program keeps the list of messages, and no longer. So "memory" depends on how long you're asking it to last.

SpanWhat survivesWhere it lives
Between stepsEvery earlier message and tool resultThe message list in your program
Between sessionsNothing, unless you saved itA file or database you write

Trace of Sam, a student, visiting twice:

  1. Monday: Sam says "I finished laser training." The assistant answers, and the program ends. The message list is thrown away.
  2. Wednesday: Sam asks "Can I book the laser?" A fresh message list starts, with no sign of Monday.
  3. The model can't know. It has to ask, or look at a record your program saved.

So the model itself remembers nothing across sessions. Your program does, by saving things and loading them back in.

Retrieval and notes 3 min

Two jobs are left: finding the right manual page, and remembering Sam. Both mean putting something outside the window and bringing back only what's needed.

Retrieval is searching a store of documents and putting only the best matches into context. Instead of loading a 300-page laser manual, you give the model a search_manuals tool and it pulls pages when it needs them. Anthropic calls this loading "just in time" (Anthropic).

Notes are facts the agent writes to a file or database so a later session can read them. Claude's memory tool works this way: the model asks to read or write files, and your application carries out those requests against storage you control (memory tool docs).

Worked example

Sam asks on Wednesday: "What speed do I use for 3 mm acrylic, and can I book the laser?"

  1. The program loads the system prompt, the tools and Sam's saved note: sam: laser training done 2026-11-17 (about 30 tokens).
  2. Model requests search_manuals("laser acrylic 3 mm speed"). The program returns the two best pages (about 800 tokens), not the whole manual (about 90,000).
  3. Model requests check_calendar and gets the open slots.
  4. It answers using the pages, the slots and the note, so no retraining question is needed.
  5. The program saves a new note, sam: asked about acrylic, if you decide that's worth keeping.

Cost check: 800 tokens instead of 90,000 is over 100 times fewer tokens on every later call in this request.

Summary 1 min

  • The model sees only the context you send; the whole thing is re-sent and paid for every call.
  • Between steps, your program's message list is the memory; between sessions, there is none unless you save it.
  • Retrieval pulls just the relevant pages in; notes carry facts about a student to the next visit.

Say it in your own words: without looking, explain to a teammate why the assistant doesn't paste the whole manual into every request.
