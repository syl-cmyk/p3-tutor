Context and memory: what the assistant sees, and what it keeps

By the end of this lesson you can say what goes in the assistant's context at each step, what survives to the next session, and how it finds one page in a long manual.

Objective O3: context and memory in an agent About 10 minutes
Why this matters for you

Your assistant must answer from long machine manuals and remember each student's training status between visits. Both come down to deciding what goes in the context, and that choice also drives your cost per request.

Warm-up 1 min

Recall

In the agent loop, who actually runs a tool, the model or the program around it? And what happens to the result?

Check your answer

The program runs it, then sends the result back to the model as part of its next input. That "next input" is exactly what this lesson is about.

The context window 2 min

The model only knows what's in front of it on each call. So at every step, someone has to decide what goes in.

Here's the example first. A student asks about the laser cutter, and the assistant is on its second model call:

1. System prompt + tool descriptions      ~1,500 tokens
2. Student: "Do I need training for the laser cutter?"   ~20
3. Model: search_manuals("laser cutter training")        ~30
4. Tool result: three manual chunks                      ~1,500
5. (the model is called again with ALL of the above)

That whole stack is the context window: everything the model reads for one call, with a fixed maximum size measured in tokens (a token is a small chunk of text, roughly a word or part of one). Anything outside it, the model simply doesn't know about.

You pay for the whole stack on every call, so a longer context costs more per step. Also, more isn't better: the more tokens in the window, the worse the model gets at recalling any one thing in it, which Anthropic calls context rot (source).

What is kept, and for how long 2 min

Between steps, the window keeps growing. Between sessions, it's gone. Anything you want to survive a session has to be saved somewhere else.

  1. Between steps (one request): the program re-sends the whole stack, plus the new result. That's why the model "remembers" the student's question at step 3.
  2. Between sessions (next visit): the model keeps nothing. A new session starts with an empty window, unless the program loads something into it.
A common mix-up

"The assistant remembers me from last time." It's tempting because chatbots feel like they do. But the model has no memory of its own: if a student's training status isn't saved and loaded back in, a new session starts blank.

Retrieval and notes 3 min

Both fixes work the same way: keep the big thing outside the window, and bring in only the small piece you need right now.

Retrieval pulls the relevant pieces of a big source into the window on demand, such as a few manual chunks instead of the whole manual. Notes are the reverse direction: the agent writes facts to a file or database outside the window, and loads them back in later (Anthropic's memory tool works this way, with a file-based store you manage). Anthropic's guide calls this structured note-taking, with examples like to-do lists and a NOTES.md (source).

Worked example

A student asks: "What speed should I cut 3 mm acrylic at?" Pretend the manual is 60,000 tokens and the window is 10,000.

  1. The model asks for search_manuals("laser cutter acrylic 3 mm speed").
  2. The program finds the best three chunks of about 500 tokens each and returns them: 1,500 tokens, not 60,000.
  3. The model answers from those chunks, using about 3,000 tokens in total, well under the limit.
  4. It then calls save_note(student, "asked about acrylic; not yet trained on laser"), a note for next session.
  5. Next Friday, the program loads that note into the fresh window at the start, for a few dozen tokens.

One catch: retrieval can bring back the wrong or repeated chunks, and notes can go stale (a student's status changes). So filter what you retrieve before it goes in, and update or delete old notes (source).

Summary 1 min

  • The model sees only the context window, and you pay for all of it on every call.
  • Between steps the window grows and is re-sent. Between sessions it's gone.
  • Retrieval brings small pieces of big sources in. Notes save small facts out, for later.
