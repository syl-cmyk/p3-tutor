Why a pipeline stalls: structural, data and control hazards

By the end of this lesson you can look at a short run of instructions, say which of the three kinds of hazard makes the pipeline stall, and count how many cycles the stall costs.

Warm-up 2 min

Recall

Last session you learned that pipelining overlaps instructions. A pipeline has 5 stages and each stage takes 1 cycle. With no problems at all, how many cycles does it take to finish 10 instructions? And does pipelining make any single instruction finish sooner?

Check your answer

The first instruction needs 5 cycles. Each of the other 9 finishes one cycle after the one before it, so 5 + 9 = 14 cycles. No: one instruction still takes 5 cycles. Pipelining raises throughput, the number of instructions finished per unit of time. Today's question is what breaks the "one finished every cycle" rhythm.

What a stall is 4 min

Think of a car wash with five bays in a row: soap, rinse, wax, dry, inspect. When it runs well, a new car enters as the previous one moves to the next bay, and one clean car leaves every few minutes. Now the wax bay jams. Every car behind it must wait, and the exit stays empty for a while.

A processor pipeline works the same way. We will use a classic five-stage pipeline, a standard teaching design (Utah CS 250P, lecture 5):

  • IF, instruction fetch: read the instruction from memory.
  • ID, instruction decode: work out what it does and read its source registers.
  • EX, execute: do the arithmetic, or compute an address or a branch test.
  • MEM, memory access: read or write data memory, for loads and stores.
  • WB, write back: write the result into a register.

A hazard is a situation that stops the next instruction from running in its normal cycle. A stall is what the pipeline does about it: it holds the instruction back and lets the cycles pass. The empty slot that travels down the pipeline is called a bubble. Bubbles are wasted cycles: every bubble delays everything behind it by one cycle (Edinburgh INF2C notes).

You already know the cost of an ideal pipeline: stages + instructions − 1 cycles. A stall adds to that directly:

total cycles = stages + instructions − 1 + stall cycles

Example: 6 instructions in a 5-stage pipeline with no hazards take 5 + 6 − 1 = 10 cycles. If hazards cost 3 bubbles in total, the program takes 13 cycles.

Cycles per instruction, or CPI, is cycles divided by instructions. An ideal pipeline approaches a CPI of 1. Stalls push it above 1. This is the same performance measure you met earlier, applied to a pipeline.

The key claim of this lesson: there are exactly three reasons an instruction cannot go ahead, and each one has a different cause. They are named by what goes wrong:

HazardWhat goes wrongEveryday picture
StructuralTwo instructions need the same piece of hardware in the same cycleTwo cooks need the one oven
DataAn instruction needs a value an earlier instruction has not produced yetYou cannot ice a cake before it is baked
ControlThe pipeline does not yet know which instruction comes nextYou cannot take the next turn before you read the sign
Check yourself

In a 5-stage pipeline, 8 instructions run and hazards cost 4 stall cycles in total. How many cycles does the program take?

Show the answer

16 cycles: 5 + 8 − 1 = 12 for the overlap, plus 4 stall cycles.

Structural hazards: one resource, two users 4 min

A structural hazard happens when two instructions need the same hardware in the same cycle and the hardware cannot serve both (Utah CS 250P). Picture a kitchen with one oven. One cook is baking bread, and another needs the oven for a pie. The pie waits, not because it depends on the bread, but because the oven is busy.

The classic processor case is a single memory used for both instructions and data. A load (lw) reads data memory in its MEM stage. In that same cycle, the pipeline wants to fetch a new instruction from memory in an IF stage. One memory, two requests.

The fix is usually not a stall at all. Structural hazards are removed by adding hardware: separate instruction and data caches, or a register file with enough ports (Edinburgh INF2C notes). A stall is the cheap fallback when the extra hardware costs too much, for example a rarely used divider unit. The price is that the pipeline slows down every time the conflict happens.

Cost: in Figure 1 the conflict costs exactly 1 cycle, so the four instructions finish in 9 cycles instead of 8.

Check yourself

A chip has one multiplier that cannot start a new multiply until the last one is finished. Two multiply instructions come one after the other, and the second must wait. Which hazard is this?

Show the answer

Structural. The test is: would the second instruction still wait if the first produced no value the second needs? Yes, because the multiplier is busy.

Data hazards: the value is not ready 6 min

A data hazard happens when an instruction needs a value that an earlier instruction has not finished producing. Look at this pair:

add r1, r2, r3     # r1 = r2 + r3
sub r4, r1, r5     # r4 = r1 - r5   needs the new r1

The sub reads r1 in its ID stage. But the add only writes r1 in its WB stage, three cycles after its own ID. If sub reads too early, it gets the old value of r1 and the program gives a wrong answer. So the pipeline must hold sub back. The name for this pattern is read after write, or RAW: the read must come after the write (Notre Dame CSE 30321).

We will assume the register file writes in the first half of a cycle and reads in the second half, a common teaching convention. Then sub can read in the same cycle that add writes. Count it in Figure 2.

Without any help, a dependence between two neighbouring instructions costs 2 stall cycles under this convention. Every instruction behind sub is held back too, so the bubbles cost the whole program 2 cycles.

How a pipeline reduces this cost

The value of r1 exists at the end of add's EX stage, in cycle 3, long before it is written to the register file. Forwarding (also called bypassing) adds a direct wire from where the value is computed to where the next instruction needs it. With forwarding, the add/sub pair above costs no stalls at all (Colorado State pipelining slides). You will learn the wiring in a later lesson; for now, only remember that forwarding exists and that it shrinks the cost of data hazards.

Forwarding cannot fix everything. A load such as lw r1, 0(r2) has its value only at the end of MEM. If the very next instruction uses r1 in EX, the value arrives a cycle too late, and you cannot send a value backward in time. That load-use case still needs a 1-cycle stall even with forwarding.

A common mix-up

"A stall always means a data hazard." It is tempting because data hazards are the first example in many courses, and because they are the most frequent. But Figure 1 shows a stall with no value involved at all, and the next section shows a stall that comes from not knowing the next instruction. Always ask what is the instruction waiting for before you name the hazard.

Check yourself

Which pair of instructions, back to back, has a data hazard?

Show the answer

The third pair. A data hazard needs one instruction that writes a register and a later one that reads that same register.

Control hazards: which instruction is next? 5 min

A control hazard comes from a branch. A branch such as beq r1, r2, T means: if r1 equals r2, jump to label T; otherwise carry on with the next line. The pipeline fetches one instruction every cycle, but it only learns the branch's answer when the branch reaches EX. Until then, it does not know what to fetch.

An everyday version: you are driving and the sign for your turn is hidden behind a truck. You keep going straight for a few seconds, and if the turn was the right choice, those seconds are wasted.

The simplest response is to stall: stop fetching until the branch is resolved. In this pipeline that costs 2 cycles per branch. Better pipelines predict the outcome and fetch from the guess, so they stall only when the guess is wrong (Western Ontario CS 3350). Prediction is a topic for a later lesson.

Why a loop full of branches runs slower

This answers your first question. Suppose 25% of the instructions in a loop are branches and each costs 2 bubbles. For every 100 instructions you lose 25 × 2 = 50 cycles. Your CPI goes from 1.0 to 1.5, so the loop runs 50% slower than an ideal pipeline. More branches, or a longer penalty, means more lost cycles.

That also hints at your second question. A deeper pipeline resolves branches later, so the penalty per branch grows. More stages can raise the clock speed, but each stall costs more. You will compare the two in a later lesson.
Check yourself

With a 2-cycle penalty per branch and no other stalls, 10% of a program's instructions are branches. What is the CPI?

Show the answer

CPI = 1 + (fraction of branches × penalty) = 1 + 0.10 × 2 = 1.2.

Telling them apart 3 min

When you see a stall in a sequence of instructions, ask one question: what is this instruction waiting for?

It is waiting for…HazardTypical fixes
A piece of hardware another instruction is usingStructuralAdd or split the hardware; else stall
A register value an earlier instruction has not producedDataForwarding; else stall; (load-use needs 1 stall)
The answer to which instruction to fetch nextControlPredict the branch; else stall
A second common mix-up

"Pipelining makes every instruction faster, so stalls are the only reason it is not perfect." Even with no stalls, one instruction still takes all 5 stages. The pipeline raises throughput, and hazards eat into that gain. With a perfect pipeline the CPI is about 1, not below 1, and no single instruction speeds up.

Check yourself

lw r1,0(r2) is followed directly by add r3,r1,r4, and the pipeline has forwarding. A stall of 1 cycle still happens. Why?

Show the answer

It is a data hazard (load-use). The value is not available until the end of MEM, one cycle after the add needs it in EX.

Worked example and practice 5 min

Worked example

A 5-stage pipeline has no forwarding and stalls on data hazards (register read and write in the same cycle is allowed). Count the cycles for these three instructions:

add r1, r2, r3
sub r4, r1, r5
or  r6, r7, r8
  1. Ideal count. 5 stages + 3 instructions − 1 = 7 cycles.
  2. Look for hazards. sub reads r1, and add writes r1. That is a data hazard. or uses r7, r8 and writes r6, which nobody else touches. No hazard. No branch, so no control hazard. Nothing is shared, so no structural hazard.
  3. Cost the hazard. Neighbouring dependent instructions, as in Figure 2, cost 2 stall cycles.
  4. Add. 7 + 2 = 9 cycles. The or is held up behind the sub, so it finishes in cycle 9, not 7.
Your turn

Same pipeline, no forwarding. Count the cycles for four instructions. Step 1 is done for you: the ideal count is 5 + 4 − 1 = 8 cycles.

add r1, r2, r3
sub r4, r1, r5
beq r6, r7, T      # taken, 2-cycle penalty
and r8, r9, r10    # first instruction at T

Step 2: find each hazard and say which kind it is. Step 3: cost each one. Step 4: add them up.

Show a solution

Step 2: sub reads r1 that add writes, which is a data hazard. The beq is a taken branch, which is a control hazard. The beq does not read r1 or r4, so there is no data hazard there, and nothing shares hardware. Step 3: the data hazard costs 2 cycles, and the branch costs 2 cycles. Step 4: 8 + 2 + 2 = 12 cycles.

Summary 2 min

  • A stall is a bubble: cycles when the next instruction cannot go ahead. Total cycles = stages + instructions − 1 + stall cycles.
  • Structural hazard: two instructions need the same hardware at once. Data hazard: an instruction needs a value not yet produced. Control hazard: the next instruction is unknown because of a branch.
  • Diagnose by asking what the instruction is waiting for. A stall is not always a data hazard.
  • Forwarding cuts data-hazard stalls but not the load-use case. A branch costs the cycles until it resolves, and more branches mean a higher CPI.

Say it in your own words: without looking back, explain to an imaginary friend why a loop with many branches runs slower, and name the hazard involved.
